# 2026-10-19

## 调研：为 Quartz 知识库站增加 AI 查询（方案设计，未改动代码）

项目事实：
- Quartz v5（插件化），社区插件在 `quartz.config.yaml` 的 `plugins:` 下配置；本地插件支持相对路径 source（loader 会 symlink 到 `.quartz/plugins`，入口可用 `index.js` 或 `dist/index.js`）。
- `content/` 是指向 `F:/knowledge-base` 的软链，但笔记文件已被 git 跟踪。
- 部署：`.github/workflows/deploy.yml` → GitHub Pages（纯静态，无法跑函数）。另存在 wrangler.toml（Cloudflare Workers assets）。
- 笔记规模：约 99 篇 md / 1.1MB；构建产物 `public/static/contentIndex.json` 约 558KB，114 条，字段 slug/filePath/title/links/tags/content，其中 78 条正文 >200 字，平均 4151 字，最长 22532 字。
- 加密页正文在独立的 `encryptedContentIndex.json`（shadow index），主索引不含明文。

推荐结论（低耦合接缝）：
1. 只读 `public/static/contentIndex.json` 作为语料源——它已按 ignorePatterns / private / 草稿 / 加密 过滤，无需自己解析 md，也不会泄露 private。
2. `scripts/ai-index.mjs` 作为 post-build 独立进程：分块（约 600 字，overlap 120）→ sha1 → 生成 `public/static/ai-index.json`（chunks + 量化向量 + version）。
3. 索引是构建产物的派生品：笔记改动 → 重跑 build → 索引同版本，天然不会与笔记漂移；增量用 chunk hash 缓存（`.ai-cache/`）。
4. UI 用本地插件（如 `quartz-ai/`）以 config 布局接入，不改 quartz 核心；路线 A 浏览器端 transformers.js（bge-small-zh）全静态，路线 B 可选 Cloudflare Worker `/api/ask` 做 RAG 生成。
