# 虚拟 DOM（Virtual DOM）核心思想

> 一句话概括：**用 JS 对象来描述 DOM 结构，当数据变化时，先在 JS 对象上对比差异，最后只把差异部分更新到真实 DOM，而不是直接操作 DOM**。

## 1. 为什么要有虚拟 DOM？

真实 DOM 操作代价很高：

- DOM 是浏览器重量级对象，创建、修改、查询都会触发**重排 (Reflow)、重绘 (Repaint)**
- 如果数据频繁变更，直接循环修改 DOM，性能很差

虚拟 DOM 思路：**把昂贵的 DOM 操作转移到轻量的 JS 计算**，JS 运算很快，只在最后一次性更新 DOM。

## 2. 虚拟 DOM 是什么

本质就是**普通 JS 对象**，用来描述节点信息。

示例：

js

```
// 真实DOM：<div class="box"><p>hello</p></div>
const vdom = {
  tag: 'div',
  props: { className: 'box' },
  children: [
    { tag: 'p', props: {}, children: ['hello'] }
  ]
}
```

字段含义：

- `tag`：标签名
- `props`：属性（class、id、事件等）
- `children`：子节点，文本节点直接存字符串

## 3. 完整流程

1. **生成虚拟 DOM**：根据数据，创建描述页面结构的 JS 对象树（vdom）
2. **数据改变 → 生成新虚拟 DOM**
3. **Diff 算法**：对比新旧两棵虚拟 DOM 树，找出差异（patch 对象）
4. **Patch 打补丁**：把 diff 找到的差异，一次性更新到真实 DOM

> 重点：**diff 只比较同层节点**（不跨层级对比），降低复杂度。

## 4. Diff 核心规则（React/Vue 通用思想）

1. 同层比较，不跨层级移动节点
2. 节点类型不同：直接销毁旧节点，新建节点
    
    - 旧`<div>`，新`<p>` → 删掉 div，创建 p
    
3. 节点类型相同：对比属性，只更新变化的属性
4. 列表对比（key）：
    
    - 用`key`标记节点身份，用来识别节点是新增、删除、移动，避免粗暴销毁重建
    - key 不能用 index（列表增删时容易错乱）
    

## 5. 优缺点

✅ 优点

1. **减少 DOM 操作**，批量更新，降低重排重绘开销
2. 跨平台：vdom 只是 JS 对象，可以渲染到浏览器 DOM、小程序、原生 APP（ReactNative）
3. 声明式编程：只关心数据，不用手动操作 DOM

❌ 缺点

1. 有额外开销：要创建 vdom 对象 + diff 计算
2. **并不是一定比原生快**：简单页面少量更新时，原生直接改 DOM 可能更快；大量 DOM 变更场景优势明显

## 6. 区分：虚拟 DOM ≠ 真实 DOM

- 虚拟 DOM：JS 对象，内存里，轻量，**不能直接显示在页面**
- 真实 DOM：浏览器页面节点，会渲染，操作成本高

## 7. Vue / React 差异小补充

- React：完整 Virtual DOM + Fiber（重构 diff，支持分片渲染）
- Vue2：Virtual DOM；Vue3 增加了**编译时优化**，模板编译阶段就标记静态节点，减少 diff 工作量
