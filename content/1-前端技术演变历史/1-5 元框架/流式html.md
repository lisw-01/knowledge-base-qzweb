# 流式 HTML（Streaming HTML / 流式 SSR）

> 一句话：**传统 SSR 要等整个页面全部渲染完成，一次性返回完整 HTML；流式 HTML 基于 HTTP 分块编码（Chunked Transfer Encoding），服务端一边渲染，一边把 HTML 分片（chunk）陆续发给浏览器，浏览器收到一块就直接渲染一块，不用等全部内容**Next.js

## 传统 SSR（非流式）

1. 请求进来 → 服务端**等待所有组件、所有接口全部完成**
2. 拼接完整一大段 HTML
3. 一次性发给浏览器 → 浏览器收到完整 HTML 再渲染页面

> 缺点：页面里只要有一个接口慢，**整个页面都卡住，白屏等待**。哪怕导航栏、header 很快能渲染，也必须一起等慢的模块。

## 流式 HTML 工作流程

1. 请求进来，服务端先把 ** 布局壳子（header、导航）** 渲染成第一块 HTML，立刻发给浏览器
2. 浏览器收到 header，马上渲染出页面骨架、骨架屏
3. 服务端继续并行渲染剩下组件；**每个 Suspense 边界内的组件数据准备好，就输出一块 HTML**
4. 浏览器收到新 chunk，直接插入 DOM，局部更新页面
5. 全部传输完毕，连接结束

底层：HTTP `Transfer-Encoding: chunked`，**普通 HTTP 响应**
