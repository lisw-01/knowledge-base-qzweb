> 一句话：**JS 是单线程语言（同一时刻只执行一段代码），事件循环就是"调用栈清空后，先清空所有微任务，再取一个宏任务"的无限循环——微任务永远插队宏任务。**

## 一、为什么需要事件循环

单线程 = 一段时间只能干一件事。如果 Ajax、定时器、DOM 事件都同步等待，页面就卡死了。所以：

- **调用栈**：同步代码在这里执行，栈不空不干别的
- **Web APIs**：浏览器提供的线程（定时器、网络、事件监听），到点后把回调放进任务队列
- **任务队列**：等着进调用栈执行的回调

## 二、宏任务 vs 微任务（核心中的核心）

| 类型 | 成员 | 时机 |
| ---- | ---- | ---- |
| **微任务** | `Promise.then/catch/finally`、`queueMicrotask`、`MutationObserver`、**await 之后的代码** | **当前宏任务结束后、渲染前，一次性清空全部** |
| **宏任务** | `setTimeout/setInterval`、I/O、UI 事件、`setImmediate`(Node) | 每轮循环取**一个**执行 |

一轮循环的顺序：

```
执行一个宏任务（比如整段 script）
  → 清空【全部】微任务队列
  → （必要时渲染 UI）
  → 取下一个宏任务
```

## 三、经典输出题（必须秒杀）

js

```
console.log('1')

setTimeout(() => console.log('2'), 0)

Promise.resolve().then(() => {
  console.log('3')
  Promise.resolve().then(() => console.log('4'))   // 微任务里再产生的微任务，本轮继续清
})

console.log('5')

// 输出：1 5 3 4 2
```

解析：

1. 同步：`1`、`5`（setTimeout 注册宏任务，Promise.then 注册微任务，都不执行）
2. 整段 script（宏任务）结束 → 清微任务：`3`，又冒出微任务 `4`，继续清：`4`
3. 取下一个宏任务：`2`

> 就算 `setTimeout(fn, 0)` 也不是立即执行：它排在**宏任务**队列，永远等微任务清完才轮到它。

## 四、async/await 的本质

`async/await` 是 Promise 的语法糖，**await 之后的代码 = then 的回调（微任务）**：

js

```
async function foo() {
  console.log('a')            // 同步执行
  await bar()                 // bar() 同步执行；这里"让出"主线程
  console.log('b')            // 相当于 then(() => console.log('b'))，微任务
}
```

对比题：

js

```
async function f() {
  await Promise.resolve()
  console.log('await 后')
}
setTimeout(() => console.log('timeout'))
f()
Promise.resolve().then(() => console.log('then'))

// 输出：await 后 → then → timeout
// 注意：现代引擎里 await 后续与 .then 同级排队（先注册的 await 先出），
//       老规范里 await 会多吃一层微任务——记住"都是微任务、按注册顺序"即可
```

## 五、Node 的事件循环（简版）

Node 也有事件循环，但分**六个阶段**（ timers → pending → poll → check → close ），两个关键差异：

1. 微任务时机：**每个阶段切换之间**清空微任务（不是每个宏任务后）
2. `process.nextTick` 优先级**高于** Promise 微任务

```
setTimeout(() => console.log('timeout'))          // timers 阶段
setImmediate(() => console.log('immediate'))      // check 阶段
Promise.resolve().then(() => console.log('promise'))
process.nextTick(() => console.log('nextTick'))

// 输出：nextTick → promise → timeout/immediate（这两个顺序不确定）
```

> Node 11+ 后为了对齐浏览器，每执行完一个宏任务也会清微任务，行为已趋同。

## 六、实战关联

- `setTimeout(fn, 0)` 的真实用途：把任务挪到"本轮结束后"执行，让浏览器先渲染/先处理输入（React 早期批量更新就这么干的）
- Vue 的 `nextTick`、批量 DOM 更新走的就是微任务（Promise.then）——见 [[3-2 Vue核心原理]]
- 长任务（>50ms）会阻塞渲染导致 INP/LCP 变差，解法是拆任务：`scheduler.yield()` / `setTimeout` 分片
