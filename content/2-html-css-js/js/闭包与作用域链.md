> 一句话：**闭包 = 函数 + 它定义时的词法环境：内层函数引用了外层变量，外层函数就算执行完了，这些变量也不回收——这是 JS 实现私有状态、柯里化、回调记忆的根基，也是各种"值不对了"bug 的来源。**

## 一、先看作用域链

JS 变量查找是**词法作用域**（由代码书写的位置决定，不是调用时机决定）：

```
全局作用域
  └─ 外层函数作用域
       └─ 内层函数作用域
```

内层访问一个变量，就近逐层向外找，找到全局还没找到才报 `ReferenceError`。

## 二、闭包的经典定义

js

```
function counter() {
  let count = 0            // 本该随 counter 结束而销毁
  return function add() {
    count++                // 但 add 引用着它 → 被留在内存里
    return count
  }
}

const add = counter()      // counter 执行完了
add()  // 1
add()  // 2  ← count 还活着，而且外部谁也碰不到它
```

**判断闭包的三个条件：**

1. 函数嵌套
2. 内层引用了外层变量
3. 内层函数被拿到外面（返回/赋值给全局/作为回调传出）

## 三、必须掌握的经典题：var 循环

js

```
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0)
}
// 输出 3 3 3：var 无块级作用域，三个回调共享同一个 i，
// 定时器跑的时候循环早结束了，i 已经是 3
```

**三种修法：**

js

```
// ① let：每次循环生成新的块级作用域变量（推荐）
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0)   // 0 1 2
}

// ② IIFE：用闭包把当时的 i 拷贝进去
for (var i = 0; i < 3; i++) {
  (function(j) {
    setTimeout(() => console.log(j), 0) // 0 1 2
  })(i)
}

// ③ setTimeout 第三个参数
for (var i = 0; i < 3; i++) {
  setTimeout((j) => console.log(j), 0, i) // 0 1 2
}
```

## 四、闭包的四大实战应用

### 1. 私有变量（没有 class #field 之前的标准做法）

js

```
function createWallet() {
  let balance = 0                 // 外部无法直接改
  return {
    deposit(n) { balance += n },
    get() { return balance }
  }
}
```

### 2. 防抖 / 节流（闭包存定时器）

js

```
function debounce(fn, delay) {
  let timer = null                // 闭包变量：跨多次调用存活
  return function(...args) {
    clearTimeout(timer)
    timer = setTimeout(() => fn.apply(this, args), delay)
  }
}
```

### 3. 柯里化 / 参数复用

js

```
const add = a => b => a + b       // a 被闭包记住
const add10 = add(10)
add10(5)  // 15
```

### 4. 缓存/记忆化

js

```
function memoize(fn) {
  const cache = new Map()
  return function(arg) {
    if (!cache.has(arg)) cache.set(arg, fn(arg))
    return cache.get(arg)
  }
}
```

## 五、闭包的坑：过期快照（React Hooks 重灾区）

React 函数组件**每次渲染都是一次新函数调用**，闭包捕获的是**那一次渲染的状态快照**：

jsx

```
function Chat() {
  const [msg, setMsg] = useState('')

  useEffect(() => {
    const id = setInterval(() => {
      console.log(msg)      // ❌ 永远是 effect 创建那一刻的 msg（空字符串）
    }, 1000)
    return () => clearInterval(id)
  }, [])                    // 空依赖 → effect 只跑一次 → 闭包冻住了
}
```

修法：函数式更新 `setMsg(m => ...)`、正确填写依赖数组、或用 ref 存最新值。详见 [[3-3 React核心原理]]。

> 一切"闭包值不对"的病根都一样：**你读的是创建闭包那一刻的快照，不是现在的值。**

## 六、内存泄漏注意事项

- 闭包变量**只要有引用就不回收**，把闭包挂到长生命周期对象（全局、DOM 节点、定时器）上又不用了 → 泄漏
- 典型：给按钮绑了引用大对象的回调，按钮移除了但还留着引用 → 解绑/置 null
- Chrome DevTools → Memory → 堆快照，按 Retainers 查谁拉着对象不放

## 七、一句话总结

| 概念 | 一句话 |
| ---- | ---- |
| 作用域链 | 就近向外找变量，由书写位置决定 |
| 闭包 | 函数带着它出生时的环境一起跑路 |
| 用途 | 私有变量、防抖节流、柯里化、记忆化 |
| 坑 | 快照过期（React hooks）、内存泄漏 |
