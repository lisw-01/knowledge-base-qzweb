# 创建脚手架（CLI）

> 核心一句话：**脚手架 = 用 Node 写一个 CLI 命令，交互式收集项目参数 → 拉取/渲染模板文件 → 自动装依赖 + 初始化 git，把"新建项目"压缩成一条 `npx create-xxx my-app` 命令。**

***

## 一、脚手架到底在干什么

```
用户执行 create-xxx my-app
  → commander 解析参数（项目名、--template vue）
  → @inquirer/prompts 交互问答（要 TS 吗？要 ESLint 吗？）
  → degit 拉取模板（git 仓库快照 / 本地 / npm 包模板）
  → handlebars 用答案渲染模板变量（{{projectName}}）
  → fs-extra 写入目标目录（已存在则询问覆盖）
  → execa 跑 npm install + git init
  → 输出 "cd my-app && npm run dev"
```

***

## 二、核心库选型

| 库 | 作用 | 替代方案 |
| ---- | ---- | ---- |
| `commander` | 命令注册 + 参数解析（`--xxx`、`[name]`） | yargs（更重） |
| `@inquirer/prompts` | 交互问答（选择、确认、输入） | inquirer（老 API，仍可用）、prompts |
| `picocolors` | 终端着色 | chalk（v5 纯 ESM） |
| `ora` | loading 动画 | nanospinner（更轻） |
| `execa` | 执行子进程（`npm install`、`git clone`） | 原生 `node:child_process` |
| `fs-extra` | 文件操作增强（递归拷贝/删除） | 原生 `fs/promises` + cp |
| `handlebars` / `ejs` | 模板变量渲染 | 二选一 |
| `degit` | 下载 git 仓库**不带 `.git` 历史** | 直接 `git clone` |

> 现代 CLI（`create-vite` 等）越来越倾向用 `@inquirer/prompts` + `execa` + `picocolors` 这套轻量组合，规避 CommonJS/ESM 切换的坑。

***

## 三、CLI 包本身的项目结构

```
create-xxx/
├─ bin/
│  └─ cli.js          # 入口（带 shebang）
├─ src/
│  ├─ index.js        # 主流程编排
│  ├─ ask.js          # 交互问答
│  ├─ download.js     # 拉取模板
│  ├─ render.js       # 模板变量渲染
│  └─ utils.js        # 目录校验、日志、装依赖
├─ templates/         # 内置模板（也可放独立仓库）
├─ package.json
└─ README.md
```

`package.json` 关键字段：

```json
{
  "name": "create-xxx",
  "version": "1.0.0",
  "type": "module",
  "bin": {
    "create-xxx": "bin/cli.js"
  },
  "files": ["bin", "src", "templates"],
  "engines": { "node": ">=18" },
  "dependencies": {
    "commander": "^12.0.0",
    "@inquirer/prompts": "^7.0.0",
    "picocolors": "^1.1.0",
    "ora": "^8.0.0",
    "execa": "^9.0.0",
    "fs-extra": "^11.0.0",
    "handlebars": "^4.7.0",
    "degit": "^2.0.0"
  }
}
```

要点：

- `name` 以 `create-` 开头 → `npm init xxx` / `npx create-xxx` 都能跑（npm 5.2+ 自动走这条约定）
- `bin` 字段把命令名映射到入口脚本，npm 安装时自动加可执行权限
- `type: "module"` → 全用 ESM `import`；要兼容老 Node 用 CJS 就去掉这行并改 `require`
- `files` 白名单发布，只发必要文件

## 四、逐步实现

### 4.1 入口脚本 `bin/cli.js`（shebang 必须第一行）

```js
#!/usr/bin/env node
import { run } from '../src/index.js'

run(process.argv.slice(2)).catch((e) => {
  console.error(e)
  process.exit(1)
})
```

> shebang `#!/usr/bin/env node` 必须在文件**第一行**，前面不能有空行/注释，否则不生效。

### 4.2 注册命令与参数（commander）

```js
// src/index.js
import { Command } from 'commander'

const program = new Command()

program
  .name('create-xxx')
  .description('创建一个 xxx 项目')
  .argument('[project-name]', '项目名', 'my-app')
  .option('-t, --template <name>', '指定模板（vue / react）')
  .version('1.0.0')
  .action(async (projectName, options) => {
    await createProject(projectName, options)
  })

export function run(argv) {
  program.parse(argv)
}
```

用法：`create-xxx my-app -t vue` → `projectName='my-app'`，`options.template='vue'`

### 4.3 交互问答（@inquirer/prompts）

```js
// src/ask.js
import { select, confirm } from '@inquirer/prompts'

export async function ask(options) {
  const template = options.template || await select({
    message: '选择技术栈',
    choices: [
      { name: 'Vue 3', value: 'vue' },
      { name: 'React', value: 'react' },
    ],
  })
  const useTs = await confirm({ message: '使用 TypeScript？', default: true })
  const useEslint = await confirm({ message: '集成 ESLint？', default: true })
  return { ...options, template, useTs, useEslint }
}
```

### 4.4 拉取模板（三种策略选一种）

| 策略 | 优点 | 缺点 |
| ---- | ---- | ---- |
| 仓库内置 `templates/` | 不依赖网络，最快 | 模板更新要发新版 CLI |
| 独立 git 仓库（degit / git clone） | 模板可独立迭代 | 需联网；私有仓库要凭证 |
| 模板发成 npm 包 | 版本可控、跨端 | 多一层依赖 |

```js
// src/download.js —— 策略二：用 degit 拉取 git 仓库快照（不带 .git）
import degit from 'degit'

export function downloadTemplate(template, dest) {
  const emitter = degit(`your-org/template-${template}`, {
    cache: false,
    force: true,
  })
  return emitter.clone(dest)
}
```

> 要保留 git 历史就用 `execa('git', ['clone', url, dest])`；degit 拉的是仓库快照、更轻。

### 4.5 渲染模板变量（handlebars）

模板文件里写 `{{projectName}}`、`{{useTs}}` 占位符，渲染时替换：

```handlebars
// 模板里的 package.json
{
  "name": "{{projectName}}",
  "version": "0.0.0"
}
```

```js
// src/render.js
import Handlebars from 'handlebars'
import { readFile, writeFile } from 'node:fs/promises'
import path from 'node:path'
import { glob } from 'glob'

const BINARY_RE = /\.(png|jpe?g|gif|ico|woff2?|ttf|mp4)$/i

export async function renderDir(dir, data) {
  const files = await glob('**/*', { cwd: dir, nodir: true, dot: true })
  for (const rel of files) {
    const abs = path.join(dir, rel)
    if (BINARY_RE.test(abs)) continue              // 二进制跳过，别用 utf8 读
    const raw = await readFile(abs, 'utf8')
    if (!raw.includes('{{')) continue             // 无占位符跳过
    const out = Handlebars.compile(raw)(data)
    await writeFile(abs, out)
  }
}
```

> ⚠️ 文件名也常带占位符（如 `{{projectName}}.config.js`），渲染完记得按结果重命名。

### 4.6 目录校验与写入

```js
// src/utils.js
import fs from 'fs-extra'
import path from 'node:path'
import { confirm } from '@inquirer/prompts'

export async function ensureTarget(name) {
  const target = path.resolve(process.cwd(), name)
  if (fs.existsSync(target)) {
    const ok = await confirm({
      message: `目录 ${name} 已存在，覆盖？`,
      default: false,
    })
    if (!ok) process.exit(0)
    await fs.remove(target)
  }
  await fs.ensureDir(target)
  return target
}
```

### 4.7 自动装依赖 + git init

```js
// src/utils.js（续）
import ora from 'ora'
import { execa } from 'execa'

export async function install(target) {
  const spinner = ora('安装依赖...').start()
  await execa('npm', ['install'], { cwd: target, stdio: 'ignore' })
  spinner.succeed('依赖安装完成')
}

export async function initGit(target) {
  try {
    await execa('git', ['init'], { cwd: target })
    await execa('git', ['add', '-A'], { cwd: target })
    await execa('git', ['commit', '-m', 'init'], { cwd: target })
  } catch {
    // 用户没装 git 也不阻塞
  }
}
```

### 4.8 主流程编排 + 成功提示

```js
// src/index.js（续）
import pc from 'picocolors'
import { ask } from './ask.js'
import { downloadTemplate } from './download.js'
import { renderDir } from './render.js'
import { ensureTarget, install, initGit } from './utils.js'

async function createProject(name, options) {
  const target = await ensureTarget(name)
  const data = await ask(options)
  await downloadTemplate(data.template, target)
  await renderDir(target, { projectName: name, ...data })
  await install(target)
  await initGit(target)

  console.log(pc.green(`\n✓ 项目创建完成：${name}\n`))
  console.log(`  cd ${name}`)
  console.log(`  npm run dev\n`)
}
```

## 五、本地调试（不用发布就能跑）

```bash
# 在 CLI 包目录里，建立全局软链
npm link

# 之后任意目录都能用
create-xxx my-app

# 调完清理
npm unlink -g create-xxx
```

> 直接 `node bin/cli.js my-app` 比软链更快，但 shebang 与 PATH 行为不一样，最终验证还是建议 `npm link`。

发布命令见 [[Npm 指令]]、源切换见 [[Nrm 指令]]，核心三步：

## 七、模板存放策略怎么选

| 场景 | 推荐 |
| ---- | ---- |
| 个人/团队内部工具，模板变化少 | 模板放 CLI 仓库内 `templates/` |
| 模板频繁迭代、要支持多版本 | 独立 git 仓库 + degit，按 tag 区分版本 |
| 给外部用、要锁定版本 | 模板发 npm 包，CLI 指定版本范围 |

## 八、常见坑

| 现象 | 原因 | 解决 |
| ---- | ---- | ---- |
| `command not found: create-xxx` | 没装 / `bin` 字段写错 / `npm link` 没生效 | 核对 `package.json` 的 `bin`；重跑 `npm link` |
| shebang 不生效 | 第一行不是 `#!/usr/bin/env node` | 必须文件第一行，前面无空行 |
| `require is not defined` | 没 `type: module` 却用 `import` | 加 `"type": "module"`，或改 `.mjs` 扩展 |
| 模板图片/字体损坏 | 用 `utf8` 读二进制 | 渲染前按扩展名跳过二进制（见 4.5） |
| Windows 下没颜色 | 老终端不支持 ANSI | picocolors 自动降级；必要时配 `FORCE_COLOR=1` |
| `npm install` 在生成的项目里卡住 | 用了淘宝镜像且包缺失 | CLI 里检测并切官方源，或提示用户 |
| 发布 403 | 用了淘宝镜像源 / 名字被占用 | 切官方源 [[Nrm 指令]]；换包名 |

## 九、一句话串完整链路

```
shebang 入口 → commander 解析参数 → @inquirer 问答 → degit 拉模板
→ handlebars 渲染 → fs-extra 写盘 → execa 装依赖/git init → 提示用户
```
