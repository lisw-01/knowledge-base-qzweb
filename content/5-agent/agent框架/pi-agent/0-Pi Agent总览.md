# Pi Agent 总览

> 核心一句话：**Pi 把「Agent = LLM + 工具 + 循环」这条公式工程化到了极致——约 418 行核心循环、4 个默认工具、<1000 token 系统提示；其余一切（模型接入、扩展、会话、远程协议）拆成职责单一的包，按需组合**。
> 本篇是 pi-agent 笔记的**入口**：先建立整体认知（本篇 + 1/2 两篇），再按需逐个深入功能设计点（`设计点/` 系列 9 篇）。

## 一、30 秒认识 Pi

- **是什么**：终端里的极简开源 Coding Agent（MIT，90K+ Star），同时是一套可复用的 Agent 运行时（monorepo，`@earendil-works/*` 系列 npm 包）
- **哲学**：前沿模型本身就会当编码代理，框架不该过度指导模型——所以内核只留最必要的，其余全部外置
- **三个反常识设计**：
    1. 刻意不内置：MCP、子代理、权限弹窗、计划模式、任务清单（需要时再装扩展）
    2. 没有沙箱：以启动用户的完整权限运行（生产必须容器化 + 钩子拦截）
    3. 上下文极省：每轮发送的上下文约为同类工具的 1/3（Databricks 基准），成本显著更低

## 二、认知地图：包结构一图流

```
pi-mono（monorepo，lockstep 统一发版）

  ┌─ 核心三层（严格单向依赖）──────────────────────┐
  │                                                 │
  │  L1 pi-ai           统一 LLM 接口                │ ← 40 家厂商抹平成一个 stream()
  │    ↑                                            │
  │  L2 pi-agent-core   Agent 内核                   │ ← 循环/事件/工具编排，无 UI 无业务
  │    ↑                                            │
  │  L3 pi-coding-agent 产品组装层（SDK 入口）        │ ← 内置工具/会话/扩展/Skills/运行模式
  │                                                 │
  └─────────────────────────────────────────────────┘
  pi-tui                                终端 UI（差分渲染，可独立用）
  pi-protocol / pi-client / pi-server   CBOR 远程会话栈（实验性）
  sqlite-node ｜ telemetry ｜ evals     存储 / 遥测 / 评测 支撑包
```

三个核心包的一句话职责：

| 层 | 包 | 干什么 | 深入 |
|----|----|--------|------|
| L1 | pi-ai | 统一 LLM API：多厂商适配、归一化流式事件、compat 开关、凭证管理 | [[1-模型适配]] |
| L2 | pi-agent-core | Agent Loop、事件总线、工具调度、会话原语（不含 UI/业务） | [[5-Agent循环]] [[3-工具系统]] [[7-事件系统]] |
| L3 | pi-coding-agent | 组装成完整编码代理：内置工具、会话持久化、扩展、Skills、四种运行模式 | [[2-上下文工程]] [[4-会话系统]] [[6-扩展系统]] |

### 路径 B：逐个功能设计点（本笔记集的核心，渐进深入）

按序读 `设计点/` 文件夹 9 篇。**顺序刻意对应〔（2）agent开发需要处理的功能点和设计原则〕的七层功能地图，自下而上**：前 7 篇的编号即层号，第 8 篇是护栏+运营的综合实践，第 9 篇是七层之外的产品化。每篇同一个骨架：**解决什么问题 → Pi 怎么做 → 设计启示（迁移到你自己的 Agent 开发）**：

| 顺序 | 设计点 | 对应（2）的层 | 解决的问题 | 一句话方案 |
|------|--------|--------------|-----------|-----------|
| 1 | [[1-模型适配]] | ① 模型层 | 40 家厂商格式全不一样，怎么抹平？ | 统一类型 + 归一化流 + compat 开关 + never-throw |
| 2 | [[2-上下文工程]] | ② 提示层（compaction 兼④） | 每轮 prompt 塞什么？长会话怎么不爆窗？ | 常驻最小化 + 按需注入 + compaction |
| 3 | [[3-工具系统]] | ③ 工具层 | 模型给的参数能信吗？前后怎么插逻辑？换执行环境怎么办？ | 四阶段流水线 + Operations 可插拔 |
| 4 | [[4-会话系统]] | ④ 记忆层 | 会话怎么存？怎么"回到过去重来"？ | JSONL 追加 + 树形分支 + 多后端 |
| 5 | [[5-Agent循环]] | ⑤ 控制层 | 循环到底循环什么？插话/追问/停止怎么办？ | 双层 while + steering/followUp 队列 + 停止钩子 |
| 6 | [[6-扩展系统]] | ⑥ 护栏层（插件化） | 不改内核怎么加能力、拦截行为？ | 事件钩子 + registerTool + virtual modules |
| 7 | [[7-事件系统]] | ⑦ 运营层（地基） | UI/扩展/持久化/记账怎么统一接到循环上？ | 一切皆事件，消费者全是订阅者 |
| 8 | [[8-安全与可观测]] | ⑥+⑦ 综合实践 | 无沙箱怎么安全上生产？花了多少钱怎么查？ | 三道防线 + usage 记账 + telemetry/evals |
| 9 | [[9-远程会话栈]] | 七层之外（产品化） | 终端之外怎么暴露成服务？ | CBOR 协议 + 传输抽象 + 会话租约 |
