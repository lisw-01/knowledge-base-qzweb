# 设计点 4：会话系统

> 核心一句话：**会话 = 追加式 JSONL + 树形结构（任意历史消息上可分叉，像 git branch）；SessionManager 管持久化，AgentSessionRuntime 管活跃会话的新建/恢复/分叉/导入**。
> 系列：[[0-Pi Agent总览]] ｜ 对应（2）之④记忆层 ｜ 上一篇 [[3-工具系统]] ｜ 下一篇 [[5-Agent循环]] ｜ demo：[11-sessions](../pi-sdk-demo/11-sessions)、[13-session-runtime](../pi-sdk-demo/13-session-runtime)

## 一、这个设计点解决什么问题

| 问题 | 白话版 |
|------|--------|
| 怎么存？ | 程序重启、机器重启，会话不能丢 |
| 怎么回放？ | "上次它是怎么一步步改的"要能查 |
| 怎么重来？ | "刚才那步走错了，回到之前换个思路" |
| 怎么管理多个会话？ | 列出 / 继续 / 打开指定会话 |

## 二、存储模型：entry 追加 + 树形分支

- **JSONL 文件，一条 entry 一行**（用户消息、助手消息、工具结果、compaction 记录都是 entry）——追加-only，好备份、好流式读取
- **树形结构**：`navigateTree(targetId)` 可以在**任意历史消息上分叉**，之后的发展成为新分支——像 git branch，`/tree` 命令可视化
- 价值：**"回到出错前零成本重试"**——不用重开会话重述任务，从中间某个节点直接长出新分支

SQLite 后端（可选）：`sessions / entries / branch_entries / lanes / records / facts / branch_tips / writer_leases` 等表，writer lease + 事务队列控制并发写入，带 FTS 全文搜索。JSONL 和 SQLite 实现同一套存储接口。

## 三、SessionManager：持久化五种姿势（demo 11）

| 方法 | 效果 |
|------|------|
| `SessionManager.inMemory()` | 内存会话，不落盘（测试用） |
| `SessionManager.create(cwd)` | 新建持久化会话 |
| `SessionManager.continueRecent(cwd)` | 继续最近会话，没有则新建 |
| `SessionManager.list(cwd)` | 列出全部会话（id + 首条消息摘要） |
| `SessionManager.open(path)` | 打开指定会话文件 |

## 四、AgentSessionRuntime：活跃会话的替换（demo 13）

会话替换四条路径，**都先触发 `session_before_switch` / `session_before_fork` 扩展钩子（可取消），再 teardown 当前会话**：

| 路径 | 干什么 |
|------|--------|
| `newSession()` | 新建 |
| `switchSession(file)` | 恢复到已有会话 |
| `fork()` | 按 entry 分支/克隆 |
| `importFromJsonl()` | 导入 JSONL 再 resume |

关键模式（demo 13 的 `bindSession`）：**运行时替换会话后，所有会话级订阅和扩展绑定必须重新绑到 `runtime.session`**——写多会话应用时最容易漏这一步。

## 五、远程模式下的会话租约

远程栈里会话带租约语义：`exclusive`（独占，创建者持有）/ `shared`（共享，多端附着），支持 generation 失效与清理 reconciliation → 多个客户端看同一个会话不打架（详见 [[9-远程会话栈]]）。

## 六、会话 × 事件 × 持久化怎么配合

```
AgentSession.prompt()
  → 持久化 entry（追加进 JSONL/SQLite）
  → 循环产生的每条消息/工具结果 → entry_appended 事件 → 落盘
  → server 模式：会话快照广播给 attached 连接
```

追加式存储 + 快照广播 + 增量事件，三者天然咬合——新客户端 attach 先拿 `SessionSnapshot` 快照，再收增量进度。

## 七、设计启示（迁移到你自己的 Agent）

1. **会话当资产管理**：可回放、可共享、可复盘——排查过程本身就是文档；对照自研七层地图的记忆层 + 运营层
2. **树形分支 = 零成本重试**：线性会话出错只能重来，树形会话可以"回到岔路口"——这个数据结构值得在设计自己的会话存储时就定下来（追加式 + parent 指针就够）
3. **存储接口化**：JSONL（简单）和 SQLite（并发+搜索）同一接口，按规模演进
4. **会话替换要有钩子**：切换前的 `before_switch` 钩子让扩展能保存状态、阻止危险切换
