# 设计点 9：远程会话栈（CBOR 协议）

> 核心一句话：**在核心三层之上叠一套传输无关的远程会话协议——CBOR 二进制帧 + ByteTransport 抽象 + 会话租约，让同一个 Agent 能被 Web UI / 远程客户端消费，而 server 不重新实现任何 Agent 逻辑**。
> 系列：[[0-Pi Agent总览]] ｜ 七层之外：把 Agent 做成服务（产品化）｜ 上一篇 [[8-安全与可观测]] ｜ 系列末篇 ｜ 详解：[[2-Pi Agent架构]] §4、[[3-Pi Agent分析]] §3~5

## 一、这个设计点解决什么问题

- 终端 TUI 之外的场景：Web UI、远程 Agent 服务、跨进程/跨机器会话
- 传输多样（WebSocket / TCP / UnixSocket），协议不想绑死任何一种
- 多个客户端要看/操作同一个会话，怎么不打架

## 二、三件套：protocol / client / server

| 包 | 职责 |
|----|------|
| `pi-protocol` | CBOR schema（typebox 定义）、framing、codec：**只做字节 ↔ 消息，不含任何业务逻辑** |
| `pi-client` | 传输无关客户端；`ByteTransport` 是任意传输的插入点；`PiClient` / `PiSessionHandle` |
| `pi-server` | 接受字节连接、帧解码、sessionId 多路分发、命令调度 |

**线格式**：4 字节 big-endian uint32 长度头 + CBOR payload；`FrameDecoder` 增量解码（任意字节分块进，完整帧出），带最大帧长校验。

**握手**：client 发 `{ type: "hello", version }` → server 回 `ServerHello`（附完整快照）或 `hello_error`。

## 三、协议消息模型

```
-- 会话条目（协议归一化）--
UserTranscriptItem / AssistantTranscriptItem / ToolTranscriptItem
  （assistant 带 status: streaming|complete|error|aborted；tool 带 status: running|complete|error）

-- 增量进度 --
TranscriptProgress: item_started / assistant_delta / item_updated / item_finished

-- 状态同步 --
SessionSnapshot（id, phase, model, transcript, queuedSteer…）
ServerSnapshot（serverId, sessions, models）

-- 命令（client → server）--
list | create | attach | detach | prompt | steer | abort | set_model | set_thinking
```

两个关键抽象：

1. **TranscriptItem 归一化**：内核的 Message 体系被折叠成三种协议条目——**远端 UI 只需要理解协议，不需要理解内核类型**，两边可以独立演进
2. **快照 + 增量**：新客户端 attach 先拿 `SessionSnapshot` 全量，再收 `TranscriptProgress` 增量——经典的状态同步模型

## 四、五层架构与租约

```
L5 pi-client        传输无关 CBOR 客户端
     ↓ WebSocket / TCP / UnixSocket 字节流
L4 pi-server        连接接入、帧解码、sessionId 多路分发、命令调度
     ↓ 调用 AgentSession / createAgentSession
L3 pi-coding-agent  产品运行时、扩展、工具、会话
     ↓
L2 pi-agent-core    Agent Loop / 事件 / 工具编排
     ↓
L1 pi-ai            统一 LLM provider
```

- **server 不重新实现 AgentLoop**：内部复用 pi-coding-agent 的 AgentSession——远程只是"换个壳"，行为和本地完全一致
- **租约**：会话可持 `exclusive`（独占）或 `shared`（共享附着）租约，支持 generation 失效与清理 → 多端并发控制
- **SSE 不原生支持**：CBOR 协议栈只有字节流 transport；要接 HTTP 得做网关适配层（POST 控制通道 + SSE 推帧），属于 pi-client/pi-server 之外的扩展
- 零连接 + 零操作 + idle 的会话会被 server 自动 dispose

## 五、设计启示（迁移到你自己的 Agent）

1. **传输无关抽象**（ByteTransport：send/close + onData/onClose/onError 四个口）就够把协议从传输里解放出来——做 Web Agent 服务时值得照抄
2. **协议条目与内核消息分离**：给远端消费方定义一套**归一化的、带 status 的** TranscriptItem，UI 和内核彻底解耦
3. **快照 + 增量事件**的同步模型：新连接先全量后增量，断线重连逻辑简单
4. **二进制协议（CBOR）+ 长度前缀帧**：比 JSON 行协议省流量、比裸 WebSocket 消息多一层自校验（schema 校验在 codec 里）
5. 如果只是本地进程间通信，不必上这套——stdio RPC 模式（JSON 行协议）就够了，**按场景选协议复杂度**
