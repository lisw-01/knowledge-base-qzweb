打包工具历史

前端打包工具历史演进

核心脉络：无打包 → 模块方案混乱 → 打包工具诞生（Browserify）→ Webpack 一统时代 → Rollup/esbuild/Vite 分流

背景前置：浏览器原生不支持模块化，早期只能通过多个<script>标签引入 js，全局变量污染、依赖顺序难管理。

从把 node 的模块搬到浏览器 → 打包一切资源 → 区分库打包 / 应用打包 → 开发环境免打包，生产打包，追求更快构建速度。

一、萌芽阶段（无打包，2010 年前）

  • 方案：多个 script 标签顺序引入，所有变量挂载 window 全局

  • 问题：

    1. 全局变量污染，命名冲突
    2. 必须严格控制引入顺序（依赖先加载）
    3. 无法压缩合并，请求多

  • 代表库：jQuery、Underscore

  • 简单合并工具：concat + 压缩工具 UglifyJS（只合并压缩，不处理模块依赖）

二、第一代：模块打包鼻祖 Browserify（2011）

目标：让浏览器可以跑 Node.js 的 CommonJS 模块

  • 核心：识别 require()，递归把所有依赖打包成单个 bundle.js

  • 用法：browserify entry.js > bundle.js

  • 局限：

    1. 只能处理 CommonJS，不支持 ES Module
    2. 只打包 JS，css / 图片等资源处理麻烦
    3. 性能差，全量打包，无代码分割

同期：RequireJS 和 SeaJS 用在浏览器直接异步加载模块（模块加载器）。

三、第二代：Webpack 崛起（2012 发布，2014 大火）

理念：万物皆模块，一切资源都可以被打包

  • 支持：CommonJS、AMD、ES Module

  • loader：处理非 JS 资源（css、less、图片、字体）

  • plugin：扩展能力（压缩、html 生成、代码分割）

  • 核心特性：

    1. Code Splitting 代码分割，按需加载
    2. 依赖图：从入口递归构建依赖图，打包所有模块

  • 版本迭代

    • Webpack1：只支持 CommonJS，loader 系统
    • Webpack2：增加 ES Module 支持，Tree-Shaking 雏形
    • Webpack3：Scope Hoisting
    • Webpack4（2018）：重大升级，零配置，splitChunks，HMR 成熟
    • Webpack5（2020）：持久化缓存、module federation、替换旧插件

地位：2016~2020 前端工程化标准标配，Vue/React 项目首选。

四、同期并行工具（2015 左右）

Rollup（2015）

定位：库打包工具（library），不是应用打包

  • 主打 ES Module，Tree-Shaking 最早做的很好
  • 输出干净的 ES 模块、cjs、umd，适合打包 SDK、组件库（Vue、React 源码都是 Rollup 打包）
  • 短板：对 css、静态资源、HMR 支持弱，不适合业务应用

Parcel（2017）

口号：零配置打包器

  • 自动识别文件，不需要写配置文件
  • 内置 babel、postcss，开箱即用
  • 底层多进程编译
  • 缺点：大型项目缓存、自定义扩展弱，生态不如 webpack，热度慢慢下降

五、新一代：esbuild（2020）

Go 语言编写，颠覆速度

  • 目标：极致编译速度，比 webpack 快几十倍
  • 只做编译打包，不做复杂插件系统；Tree-shaking、ts 转 js、压缩内置
  • 局限：插件生态简陋，不适合单独直接构建大型应用
  • 定位：底层编译引擎，很多工具底层基于 esbuild（Vite、tsup）

tsup：基于 esbuild，专门打包 js 库，替代 rollup 简单场景。

六、现代：Vite（2020，尤雨溪）

理念：开发环境利用浏览器原生 ES Module，跳过打包；生产打包用 esbuild/rollup

  1. 开发阶段：不打包，浏览器请求时按需转换，冷启动极快

    • 依赖预构建：用 esbuild 提前把第三方依赖转成浏览器可识别的 esm

  2. 生产构建：使用 Rollup 打包

    优势：极快冷启动, HMR 秒更新；Vue 官方推荐构建工具，现在新项目首选

    局限：生产打包底层还是 rollup，超大型复杂项目自定义构建逻辑不如 webpack 成熟。

对比总结

工具定位核心特点适用场景
Browserify早期打包打包 CommonJS 到浏览器古董项目，淘汰
Webpack应用打包万物皆模块，插件生态极强复杂业务项目，微前端 Module Federation
Rollup库打包优秀 Tree-shaking，输出干净 esm组件库、SDK
Parcel零配置打包零配置，多进程中小型简单项目
esbuild编译引擎Go 编写，速度爆炸底层编译，ts 快速转译
Vite现代应用构建开发环境原生 ESM，极速 HMRVue/React 新项目
