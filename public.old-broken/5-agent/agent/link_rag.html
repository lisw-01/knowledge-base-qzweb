link_RAG

link_RAG

Sep 28, 20267 min read

核心一句话：RAG = 让 LLM “开卷考试”：先从你的资料里翻出相关的那几页，垫在问题下面让它照着答。向量库只是帮你”翻书”的工具之一。

一、先讲个例子：开卷考试

LLM 是个很聪明但没读过你公司手册的学生：

  • 你问它”咱们公司退货政策是啥”，它没见过你的手册，只能瞎编（幻觉）
  • 就算把整个手册塞给它，手册几百页，上下文窗口放不下，而且大部分内容跟问题无关

RAG 的做法 = 开卷考试：

  1. 考前：把手册撕成一页一页的小纸条，每张纸条编好”内容目录”（向量化）放进一个文件柜（向量库）
  2. 考试：学生拿到问题”多久能退货”
  3. **助教（检索程序）**去文件柜翻出跟”退货”最相关的 2 张纸条，摆在学生桌上
  4. 学生（LLM）照着桌上的纸条回答，不许凭记忆瞎编
手册(500页) --撕成小纸条+编目录--> 文件柜(向量库)
问题"多久能退货" --编目录--> 去文件柜翻出最像的2张纸条 --> 摆到LLM桌上 --> LLM照着答

二、完整走一遍RAG（带每步的真实数据）

知识库就 3 句话，问题是 “买完东西多久能退”。

第 1 步：入库（一次性） —— 每条文本变成一个向量（一串数字）：

"退货需在签收后7天内申请..."  → [0.021, -0.113, 0.876, ...] （1024个数）
"会员积分100积分抵1元..."     → [-0.33, 0.52, -0.07, ...]
"客服时间9:00-21:00..."       → [0.11, 0.04, -0.55, ...]

第 2 步：问题也变成向量：

"买完东西多久能退" → [0.019, -0.108, 0.881, ...]

第 3 步：算相似度，排序取最像的（跟谁数字越接近就是谁）：

vs 第1条(退货)：相似度 0.87  ✅ 最相关
vs 第2条(积分)：相似度 0.31
vs 第3条(客服)：相似度 0.18

第 4 步：把第 1 条塞进 Prompt，让 LLM 照着答：

请仅根据以下资料回答问题：
资料：退货需在签收后7天内申请，商品需保持吊牌完好
问题：买完东西多久能退

LLM回答：签收后7天内可以申请退货，需保持吊牌完好。

看到没——LLM 全程没读过你的知识库，它只”照着桌上的纸条”答题。这就是 RAG 的全部。

三、RAG 和向量库的区别（最容易混淆的点）

一句话：RAG 是”解决方案/完整流程”，向量库只是流程里负责”存和找”的一个零件。

向量库RAG
是什么一个**工具/软件**（FAISS、Chroma、Milvus）一套**流程方案**（切块→向量化→检索→拼Prompt→LLM回答）
干什么存向量 + 按相似度快速找 TopK让 LLM 能回答”你的”知识
缺了对方行不行行：向量库还能做推荐、去重、以图搜图，跟 LLM 没关系行：RAG 早期 demo 用 Python 列表暴力遍历也能跑（本文第三节就是这么写的）

关系图：

RAG 完整流程：
  文档 → 切块 → Embedding → 【存进向量库】→ 检索TopK → 拼Prompt → LLM生成
                          └──── 向量库只负责这一小段 ────┘

数据量小（几百条以内），不用向量库，一个列表遍历就够；数据大了才需要向量库这个”专业文件柜”。先学 RAG 流程本身，向量库随用随换。

四、为什么需要 RAG（对比只用 LLM）

问题只用 LLM用 RAG
知识过时训练截止后的事一概不知知识库随时更新，查最新内容回答
私有数据公司文档/个人笔记模型没见过文档入库即可问答
幻觉没知识就瞎编强制”照资料回答”，有据可依
成本微调大模型贵、周期长不动模型，加文档即可

RAG vs 微调：给模型补知识用 RAG；改模型的说话风格/输出习惯才用微调。

五、RAG 效果不好怎么调（按排查顺序）

  1. 先查切块（80% 的问题在这）：一篇文档别整篇入库，按标题/段落切成 300500 字的小块，块间重叠 50100 字，防止关键句被切断
  2. 打印检索结果看看：把检索出来的 topK 内容打印出来人工看一眼——检索出来的块本身就不对，那是切块/Embedding 的问题，跟 LLM 无关
  3. Prompt 加强约束：“仅根据资料回答，没有就说不知道”，防止模型夹带私货
  4. 进阶优化：topK 调大 + Rerank 精排、查询改写（口语→检索句）、混合检索（语义+关键词，匹配型号编号类精确词）、相似度低于阈值直接拒答
  5. 建测试集：准备 20 个”问题+标准出处”，每次调参回归验证，别凭感觉

六、避坑清单

  1. 换 Embedding 模型 = 全量重新入库（向量空间不兼容）
  2. 检索不准 ≠ LLM 不行，先怀疑切块和检索
  3. 数据少时别急着上向量库/框架，列表暴力遍历先跑通
  4. 评测驱动优化，不做”感觉好像好了”
