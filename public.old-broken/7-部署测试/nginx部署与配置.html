Nginx部署与配置

Oct 19, 20266 min read

一句话：Nginx 在前端部署里干三件事——静态文件服务（把 dist 发出去）、反向代理（把 /api 转给后端、跨域就地解决）、性能配置（gzip + 缓存策略）。

一、安装与常用命令

配置文件位置：

  • Linux（yum/apt）：/etc/nginx/nginx.conf，站点配置放 /etc/nginx/conf.d/*.conf
  • macOS（brew）：/opt/homebrew/etc/nginx/nginx.conf

二、配置文件结构

记住三层结构 http → server → location，所有配置都是往这三层里塞指令。

三、前端部署模板（背下来）

四个必懂的点：

1. try_files $uri $uri/ /index.html;

SPA（history 路由）部署的命门：刷新 /home 时服务器上没有 /home 这个文件，最后兜底返回 index.html，交给前端路由接管。没有这行 → 刷新 404。原理见 3-1 SPA原理与前端路由。

2. root vs alias

alias 的路径要以 / 结尾；用错最典型的症状是 404。

3. 缓存策略：index.html 不缓存 + hash 资源长缓存

打包产物文件名自带 hash（app.a3f9c2.js），内容变 hash 就变 → 静态资源可以”永久”缓存；但入口 index.html 必须每次校验，否则用户锁死在旧入口上。产物结构见 打包后的web内容。

4. proxy_pass 带不带斜杠

带不带斜杠结果不同，后端路由前缀要对得上，这是反向代理最常见的 404 来源。

四、跨域：代理 vs CORS 响应头

前后端分离时，浏览器端同源请求 /api/...（同源，无跨域），Nginx 在服务器侧转发给后端——跨域根本不发生，这是生产环境的标准做法。

六、常用排错

症状排查
改了配置没生效忘了 nginx -s reload；或改错文件（被 conf.d 覆盖）
403 Forbiddenroot 目录权限不足（nginx 运行用户读不了）；或目录下没有 index 指定的文件
刷新 404没配 try_files ... /index.html
接口 404/502proxy_pass 斜杠问题 / 后端服务没起（502 = 转发目标不可达）
资源没压缩响应头看 Content-Encoding: gzip；类型没加进 gzip_types（默认只压 text/html）
SSE 不吐字忘了 proxy_buffering off，Nginx 把流攒够 buffer 才发
